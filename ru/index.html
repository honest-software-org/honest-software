Honest Software

EN·RU

Набор принципов для разработки софта, который уважает людей. По духу близко к манифесту Dogma 95 — который содрал с кино весь грим и оставил только суть — эти правила сдирают с софта всё лишнее и оставляют то, чем он должен был быть с самого начала: полезным, прозрачным и бесплатным. Никаких исключений. Никаких компромиссов.

  1. 1Никаких данных

    Приложение не должно собирать, хранить или передавать персональные данные. Никаких аккаунтов, куки, аналитики, трекинга — даже анонимного. Если софту не нужно знать кто ты — он не спросит.

  2. 2Минимум разрешений

    Приложение должно запрашивать только те разрешения, без которых оно буквально не работает. Никакого «на всякий случай», никаких тихих захватов. Если не можешь обосновать разрешение одним предложением — не получишь его.

  3. 3Никаких dark patterns

    Интерфейс не должен манипулировать. Никаких скрытых кнопок отписки, никаких пречекнутых чекбоксов, никакой искусственной срочности, никакого guilt-tripping, никаких обманных дефолтов. UI обязан уважать внимание и интеллект пользователя.

  4. 4Системная тема

    Приложение может поддерживать тёмную и светлую тему, но не должно содержать переключателя. Только системные настройки — и ничего больше. Если пользователь хочет переключить тему именно у тебя — это сигнал, что твоя тема сломана, а не запрос на фичу.

  5. 5Бесплатно навсегда

    Софт должен быть бесплатным. Никаких подписок, платных тиров, внутренних покупок, «pro»-версий. Если думаешь о монетизации — думаешь не о том.

  6. 6Open source

    Весь код должен быть открытым и выходить под лицензией MIT — включая серверную часть. Никаких проприетарных бэкендов, никакой скрытой логики. Если нельзя прочитать — значит, этого не должно существовать.

  7. 7Self-hostable

    Софт должен быть self-hostable по дизайну. Любой человек с базовыми техническими знаниями должен уметь поднять его на своей инфраструктуре. Никакого обязательного облака, никакого vendor lock-in.

  8. 8Данные принадлежат пользователю

    Если приложение управляет данными пользователя — эти данные должны быть доступны для экспорта и импорта в любой момент. Данные принадлежат пользователю — не софту, не разработчику. Если проект умирает — данные выживают.
